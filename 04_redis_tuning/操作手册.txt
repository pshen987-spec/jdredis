优化4：Redis配置微调操作手册
===================

统一测试口径
------------
MGET总聚合：100 Key
业务RTT超时判定：5ms；网络读保护超时：100ms
线程规模：THREAD_SCALE=1
阶段2：30秒
阶段3：60秒

步骤1：将三个文件放到185的 /home/s30083118/jdredis/
---------------------------------------------------------
185_master_test_opt4_tuning.sh
collect_opt4_metrics.sh
stress_test_opt4_tuning.cpp

步骤2：在185把C++源码复制到186
---------------------------------
cd /home/s30083118/jdredis
scp stress_test_opt4_tuning.cpp root@20.20.21.186:/home/s30083118/jdredis/

步骤3：在186重新编译
-----------------------
cd /home/s30083118/jdredis
g++ -O3 -std=c++11 stress_test_opt4_tuning.cpp -o stress_test_opt4_tuning -pthread -lhiredis
chmod +x stress_test_opt4_tuning
ls -l /home/s30083118/jdredis/stress_test_opt4_tuning

步骤4：在185准备并预检
-------------------------
cd /home/s30083118/jdredis
sed -i 's/\r$//' 185_master_test_opt4_tuning.sh collect_opt4_metrics.sh
chmod +x 185_master_test_opt4_tuning.sh collect_opt4_metrics.sh
bash collect_opt4_metrics.sh --check

预检必须确认185能够登录186，并能找到186上的新编译程序。

步骤5：在185正式执行
-----------------------
cd /home/s30083118/jdredis
bash collect_opt4_metrics.sh

只执行采集脚本。采集脚本会调用主控脚本、启动压测、采集指标并上传结果。

步骤6：检查新测试口径
-----------------------
客户端输出必须显示本方案版本标识、“MGET总聚合=100”“RTT超时阈值=5ms”“网络读保护超时=100ms”，验收汇总必须显示RTT超过5ms。
如果MGET仍显示800，或业务RTT阈值仍显示100ms，说明186上的旧程序没有重新编译，本轮数据无效。网络读保护显示100ms属于正常配置。

步骤7：检查本方案特有结果
---------------------------
1. CONFIG GET必须显示三项lazyfree为yes。
2. client-output-buffer-limit normal必须为512mb 256mb 60。
3. 配置证据不符合时，本轮数据无效。

步骤8：检查公共验收指标
-------------------------
1. CPU峰值和阶段平均值。
2. RX/TX峰值。
3. MGET、SET、GET、APPEND平均及最大RTT。
4. RTT超过5ms的命令数。
5. 主从复制状态、内存变化和网卡丢包。

步骤9：检查结果目录
--------------------
185本地：
/home/s30083118/jdredis/acceptance_data/<运行时间>/

206上传目录：
/home/s30083118/jdredis/acceptance_data/opt4_redis_tuning/<运行时间>/

----------------
在185当前运行窗口按 Ctrl+C。

pkill -f 'stress_test_opt4_tuning'
